# 문구 점검 매뉴얼

화면에 보이는 한국어 문구(FAQ·예시·팁·가이드·메타 설명·안내 페이지·오류 메시지)를 점검하는 체크리스트.
디자인·레이아웃·마케팅 톤 변경은 범위 밖이다. 계산 로직·수치 점검은 [`AUDIT_CHECKLIST.md`](./AUDIT_CHECKLIST.md)를 따른다.

## 점검 주기

| 시점 | 대상 |
|------|------|
| 수치·법령 변경 직후 | 해당 수치가 나오는 모든 문구 (아래 "함께 바꿀 곳") |
| 매년 1월 · 7월 | 연도 표기, "예정"·"시행" 시제, 가이드 본문 |
| 분기 1회 | 전체 체크리스트 |

## 점검 항목

### 1. 시점이 지난 문구

- "예정", "시행 예정", "~부터 적용"이 이미 지난 날짜를 가리키는지
- "현재", "최근", "올해", "신규"처럼 기준일 없는 표현 → 기준일을 적거나 뺀다
- 과거 연도 기준 수치·사례가 현행 설명에 섞여 있지 않은지 (연혁·과거 사례는 유지)
- 기관명 변경 (예: 한국감정원 → 한국부동산원, 2020.12)
- 법령 조문 번호·명칭이 현행과 같은지 (국가법령정보센터 law.go.kr)

### 2. 코드·다른 문구와의 불일치

- FAQ·예시의 숫자가 계산기(`lib/*.ts`) 결과와 같은지. 예시는 직접 다시 계산한다
- 같은 사실이 페이지마다 다르게 적혀 있지 않은지 (계산기 페이지 ↔ 가이드 ↔ `lib/seo-platform.ts` 요약 ↔ `layout.tsx` 메타 설명)
- 입력 라벨이 계산 기준과 맞는지 (예: 자녀세액공제 대상 연령)

### 3. 오탈자·문법

- 오타, 중복 단어, 조사 오류, 깨진 문장
- 숫자 표기: 천 단위 콤마, 단위 누락 (원·만원·%·%p)
- `%`(비율)와 `%p`(차이) 구분

### 4. 과장·오해 소지·법적 리스크

- 금지: "당첨 보장", "확률 상승", "100% 정확", "무조건", 특정 상품 가입 권유
- 계산 결과는 "예상"·"세전"·"참고용"임을 밝힌다
- 로또 문구는 확률을 바꾸지 않는다는 사실과 충돌하지 않게 쓴다

## 표기 규칙

- 문체: 안내·FAQ는 "~니다/~세요" 존댓말로 통일
- 날짜: 본문은 `2026.8.27` 또는 `2026년 8월 27일` 중 한 문장 안에서 섞지 않는다
- 법령: `소득세법 제59조의2`처럼 법령명 + 조문
- 금액 단위: 기존 화면 표기(`만원`)를 유지하고, 한 문장 안에서 `만 원`과 섞지 않는다
- 출처: 수치에는 기관명 또는 법령을 함께 적는다

## 함께 바꿀 곳

수치·법령 문구를 고치면 아래를 모두 검색해서 같이 고친다.

| 위치 | 내용 |
|------|------|
| `app/<계산기>/page.tsx` | 라벨, 안내 문구, 예시(ExamplesSection), FAQ(FAQSection), 팁 |
| `app/<계산기>/layout.tsx` | 메타 title·description·키워드 |
| `app/layout.tsx` | 전체 메타, 구조화 데이터(JSON-LD) 기능 설명 |
| `app/guide/*/page.tsx` | 가이드 본문·표 |
| `lib/seo.ts`, `lib/seo-platform.ts` | 가이드 요약, AI 검색용 요약, 변경한 페이지별 갱신일 |
| `app/about/page.tsx` | 계산 근거 설명 |
| `app/*/opengraph-image.tsx` | 공유 이미지 문구 |

## 검색 명령

```powershell
Set-Location -LiteralPath 'D:\개발\n-job-studio'
rg -n "예정|현재|최근|올해|신규" app components lib
rg -n "2024|2025" app components lib
rg -n "보장|무조건|100%|확률을 높|당첨 확률" app components lib
rg -n "한국감정원" app components lib
```

- Why: 시점이 지난 표현, 낡은 연도, 금지 표현 후보를 한 번에 찾는다.
- Expected Output: 각 줄을 열어 실제로 고칠 대상인지 판단한다. 검색 결과가 모두 고칠 대상은 아니다.

## 현행 기준과 이력 구분

공포·고시 전인 정부안, 입법예고, 언론 예고를 현행 기준처럼 쓰지 않는다. 공식 원문에서 공포 여부와 시행일을 확인한다. 월 원천징수용 간이세액표와 연말정산의 자녀 공제 기준은 구분한다.

과거 제도 연혁은 날짜와 맥락이 명확하면 유지한다. 이전 점검 수치를 현재값으로 복사하지 않는다. 산출 예시는 입력 조건·절사 방식까지 같은 계산 결과로 검증한다. 변경 이력과 확인 근거는 날짜별 점검 기록에 남긴다.

## 마무리

1. 수정한 문구가 들어간 페이지를 로컬에서 열어 확인한다.
2. 내용이 바뀐 페이지의 날짜만 `lib/seo.ts`와 사이트맵·구조화 데이터에 반영한다. 공통 날짜를 일괄 변경하지 않는다. 문구 수정일과 공식 근거 확인일은 구분한다.
3. `npm.cmd run check`로 테스트 → 빌드(TypeScript 포함) → lint → audit를 통과한 뒤 `git diff --check`와 diff를 검토한다.
4. 배포 후 수정 문구·모바일 줄바꿈·운영 SHA를 확인한다.
